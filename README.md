# DriverPass-System-Analysis-and-Design
DriverPass system analysis and design project for CS 255

1. Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?
The client was DriverPass, a company that wanted a system that helps students prepare for their driving tests. They needed a web-based system where students could register, purchase training packages, schedule driving lessons, take practice tests, and access online classes. The system also needed to support instructors and administrators with their daily responsibilities and make it easier for them to keep track of student progress.

2. What did you do particularly well?
I think that I did well at identifying the different users of the system and organizing their requirements. I was able to break down what students, instructors, and administrators needed and represent those interactions through different diagrams. Creating the use case diagram helped me organize the system's functions and better understand how each user would interact with them.

3. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
I'd revise the business requirements document to provide more technical detail from the very beginning. After receiving feedback on my first submission, I realized that I needed to explain more about the existing processes and the components that'd be required for the new system. I'd improve this by describing the current and proposed systems more clearly and making sure that the technical requirements are detailed enough to guide the design.

4. How did you interpret the user's needs and implement them into your system design? Why is it so important to consider the user's needs when designing?
I interpreted the user's needs by reviewing the DriverPass interview and also identifying the functions that each user would need. I used those requirements to develop the system design, including diagrams that showed how users would interact with the system and how different processes would work. I think that considering the user's needs is so important because a system could function correctly from a technical standpoint but still fail to solve the problems that it was designed for.

5. How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?
My approach is to understand what the client needs before deciding how the system should work. I'd start by gathering requirements, identifying the users, and separating functional requirements from nonfunctional requirements. After that, I'd use diagrams like use case, activity, and sequence diagrams to plan how the system should function. I'd also review the design against the original requirements to make sure that nothing was overlooked.
